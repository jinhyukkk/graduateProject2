# 자기교정 Text-to-SQL 논문 — 한국어 학술 자연성 검토 가이드

**Korean Academic Naturalness Review Guide**

본 문서는 자기교정 Text-to-SQL 논문(KITS 제출본, [docs/논문_초안.md](../docs/논문_초안.md))의 본문 편집 시 반드시 적용해야 하는 자연어 스타일 규칙을 정리한 단일 출처(Single Source of Truth)다.

**용도**: 모든 본문 편집 작업(paper-writer-kr 호출, Edit 도구 직접 사용, 신규 섹션 작성) 전에 반드시 본 문서를 사전 적용한다. 새 위반 표현이 발견되면 본 문서에 추가 후 본문에 적용한다.

**원칙**:
- *한국어로 자연스러운가*
- *학술 톤에 맞는가*
- *사실 범위를 정확히 지키는가*
- *KITS 양식과 정합하는가*

## 2. 톤 규칙

### 2.1 학술 톤 의무

- **한국어 학술 본문 톤** 유지 (KITS 양식)
- 구어체·일상어·SNS 어휘 회피 (예: "되어진", "시켜야", "그러므로 그래서")
- 자기 변호조 ("발견 지향", "본 마감 안에서") 즉시 정정
- 과잉 주장 ("최초/유일/완벽/항상/결정적/명백히") 즉시 정정 또는 격하

### 2.2 한·영 톤 정합

- 한국어 본문 격하 표현은 영문 abstract·title도 동일 격하
- 영문 abstract에서 약어 단독 반복 회피 (첫 등장 풀이만)
- 한국어 약어 풀이 이미 정착되었으면 영문도 풀이 강화

### 2.3 학회명·메타 정보 본문 노출 금지

- 학술 본문 안에 *학회 제출 프로세스 메타* 등장 금지 (KITS·마감·제출본·발표용)
- 단, 정식 메타 필드(line 7 투고 학회) 는 보존
- 결론 절에서 학회명 직접 언급 금지 ("한국IT서비스학회의 가치에 부합" → "한국 IT 서비스 산업의 요구에 부합")

## 3. 사실 정확성 규칙

### 3.1 일반화 범위 명시

- 본 연구가 *측정한 환경* 과 *주장 범위* 를 명확히 분리
- HRDB 257건 — *한국 인사 도메인 사례 연구*, BIRD dev_300 — *외부 학술 벤치마크 표본*
- "한국 기업 전반"·"모든 한국 시스템" 등 광역 일반화 금지

### 3.2 자발 인정 (한계 절)

본 연구의 한계는 §6.4 한계 절에 *자발적으로* 인정. 사후 reviewer 지적보다 사전 인정이 평가 유리.

핵심 자발 인정 항목:
1. HRDB 스키마-온리 + 단일 ERP 기반 한정 (한계 1)
2. RQ1 임계값 30% 사후 정의 (한계 7)
3. 분자 NLI 의존성 (한계 8)
4. 단일 NLI 도구 한정 (한계 10)
5. 임계값 sensitivity 측정 범위 (한계 12)
6. 측정 완료 1.5계층 / 향후 측정 2.5계층 (한계 13)

### 3.3 사전 등록 부재 정직 인정

- 본 연구의 RQ1 진단 가설 임계값(EIED ≥ 30%)은 *분석 시점에 정식화* 된 *사후 정의* 임을 명시
- "사전 등록 임계값이 아니다" 명문화
- commit hash 인용 시 *실제 commit이 그 임계값을 등록한 시점인지* 검증 후 인용 (검증 안 된 hash 인용 금지)

### 5.3 신규 위반 발견 시

새로 어색한 표현이 발견되면:

1. 본 문서 §1 매핑 표에 추가 (금지 표현 + 정정 표현 + 사유)
2. 본문 정정
3. §5.2 grep 명령에 새 패턴 추가
4. 변경 이력 changelog에 기록

### 5.4 정정 우선순위

- **Critical**: 사실 과장, 메타 표현, KITS 양식 위반 (즉시 정정 필수)
- **Major**: 영어 직역 metaphor, 신조어 약어 (라운드 단위 정정)
- **Minor**: 일관성 다듬기, 어휘 통일 (제출 직전 1회)

### 5.5 단순 치환 vs 문장 재구성

- 단순 단어 치환으로 자연스러우면 그대로 적용
- 치환 후 문맥이 어색해지면 *문장 단위 재구성* 적용 (changelog에 사유 명시)
- 의미 변화 발생 시 사용자 확인 (자동 진행 금지)
