# 서사 재프레이밍 설계서 (Day 1-2 산출물)

**작성일**: 2026-04-25
**목적**: 파일럿 실험에서 RQ1(NLI가 EX 향상에 기여) 가설이 Null 방향으로 관측되었으므로, 논문의 기여 서사를 "교정 축 기여"에서 "**진단·안전성·독립 지표**" 축으로 재정렬한다. n=1,534 본 실험 결과와 무관하게 논문이 생존 가능한 프레임을 확보하는 것이 목표.

> **용어 주 (2026-04-25 후속 결정)**: 본 설계서는 초기에 새 지표명으로 "**EIED (E_intent Exclusive Detection)**"를 도입했으나, 검토 회의를 앞두고 이 약어가 지나치게 생소하다는 판단에 따라 **본문에서는 신조어·약어를 도입하지 않고 서술형**으로 전환했다. 이 문서 내 EIED 표현은 설계 당시의 임시 용어로, 최종 논문([docs/논문_초안.md](../docs/논문_초안.md))에서는 "**실행 검증이 통과시킨 사각지대 중 NLI가 독립적으로 탐지한 비율**" 또는 표 라벨로 "**NLI 독립 탐지율(%)**"로 풀어쓴다.

## 1. 문제 진단

### 1.1 파일럿이 밝힌 구조적 사실
| 관측 | 수치 | 함의 |
|---|---|---|
| Full SC-TSQL EX | 50.0% (n=50) | — |
| −NLI 트리거 EX | **52.0%** (n=50) | NLI가 오히려 -2pp (방향은 반대, 크기는 1건 차이로 결정 불가) |
| E_intent 감지율 | 66.0% | NLI 자체는 **잘 탐지**함 |
| Consistency@0.75 | 34.0% | NLI가 판정한 "일치" 비율 |
| **CSR (Correction Success Rate)** | **0.0%** | 자기교정 루프가 단 한 건도 성공시키지 못함 |
| 0-round 종료 | 46/50 (92%) | GPT-4o 초기 SQL의 고신뢰로 루프가 거의 발동 안 함 |

### 1.2 "EX 향상"으로는 왜 살아나기 어려운가
- 46/50이 0-라운드 종료 → 자기교정 루프 전체가 평균 EX에 미치는 기여 상한이 매우 작음.
- conf≥0.9 고신뢰 오답이 25/25 → confidence gating이 의미를 가지려면 gating을 느슨하게 해야 하는데, 그러면 올바른 SQL까지 교정되어 EX가 떨어짐.
- **이 긴장은 gpt-4o 백본의 특성**이며, n=1,534로 샘플을 늘려도 해소되지 않는다.

### 1.3 그러나 NLI는 실제로 무엇인가를 탐지하고 있다
- E_intent 감지율 66% 중 실행 축에서도 잡힌 것은 일부. **의미 축 고유 탐지분이 존재**한다.
- 현재 구조(교정 트리거)는 "탐지→교정→EX 상승"의 3단계 전환을 요구하는데, 마지막 단계가 안 된다.
- **탐지 단계까지는 주장 가능**하다.

## 2. 재프레이밍: 두 갈래 시나리오

### 2.1 Primary (n=1534에서도 RQ1=Null로 확정될 경우)
**"NLI는 EX를 올리지 않는다. 그러나 실행 정확도만으로는 놓치는 의미 오류의 독립 탐지 커버리지를 제공한다."**

#### 논문 제목 후보
- (기존) 기업 데이터 접근성 향상을 위한 **자기교정** Text-to-SQL 프레임워크
- (대안 A) 기업 데이터 접근성 향상을 위한 **의도 검증 기반** Text-to-SQL 프레임워크
- (대안 B) **실행 정확도를 넘어**: Text-to-SQL의 의도 일치 진단 프로토콜

**추천**: (A). "자기교정"을 유지하되 **검증 축 확장**으로 무게 중심을 이동. CSR=0%여도 "검증기 설계"가 본 기여이므로 생존.

#### RQ 재정식화

| 구분 | 기존 | 재프레이밍 |
|---|---|---|
| **RQ1** | NLI가 EX 향상에 *기여*하는가? | NLI가 실행 기반 검증으로는 놓치는 의미 오류를 *독립적으로 탐지*하는가? (**Detection**, not Correction) |
| **RQ2** | 유형별 프롬프트가 공용보다 우월한가? | (유지) 단, 메인 지표를 "EX 향상"에서 "**유형별 교정 성공률(ECR@type)**" 로 분리 |

#### 주 지표 재구성

| 지표 | 역할 | 파일럿 현재 값 | 본 실험 목표 |
|---|---|---|---|
| **EX** | 전체 정확도 | 50% (n=50) | n=1534 확정 |
| **E_intent Detection Rate** | *신설* — 실행 통과 쿼리 중 NLI가 불일치로 잡은 비율 | 66% | 유지 |
| **E_intent Exclusive Detection** | *신설* — 실행 축에서 "통과"로 잡혀 실제 EX=0인 쿼리 중 NLI가 잡은 비율 | 측정 예정 | **핵심 수치** |
| **ICS mean / Consistency@0.75** | 의미 일치도 (전체) | 0.59 / 34% | 유지 |
| **ECR@type** | 유형별 교정 성공률 | 전 유형 측정 예정 | 본 실험 결정 |

**핵심 신설 지표**: **E_intent Exclusive Detection** (EIED)
- 정의: `EIED = |{q : exec_correct(q)==False AND exec_validator_pass(q)==True AND NLI(q,q')<θ}| / |{q : exec_correct(q)==False AND exec_validator_pass(q)==True}|`
- 의미: "실행기가 통과시켰지만 실제로는 오답"인 사각지대 중 NLI가 몇 %를 포착하는가?
- **이 수치가 30% 이상이면 RQ1은 살아난다.** (EX 기여 없어도)

### 2.2 Secondary (n=1534에서 RQ1=Yes로 회복될 경우)
- 기존 서사 유지. 파일럿은 "표본 변동성"으로 설명.
- 단, EIED도 병기하여 "탐지와 교정 기여가 모두 있음"을 이중 증명.

### 2.3 분기 조건
- n=1534 main 실험 완료 후 **Δ(Full EX − A1 EX) ≥ +1.5pp** (paired bootstrap 95% CI 하한 > 0)이면 Secondary.
- 그 외(Null, Negative)는 Primary로 확정.

## 3. 섹션별 수정 지시

### 3.1 초록 (§국문 요약)
**BEFORE**: "본 연구는 두 연구 질문을 다룬다. **RQ1.** 자연어 역번역과 NLI 기반 의미 검증은 기존 실행 기반 검증과 *독립적으로* 기여하는가?"

**AFTER (Primary)**: "본 연구는 두 연구 질문을 다룬다. **RQ1.** 자연어 역번역과 NLI 기반 의미 검증은 실행 기반 검증으로는 포착되지 않는 의도 불일치 오류를 독립적으로 *탐지*하는가? **RQ2.** 진단된 오류 유형별 전용 교정 프롬프트는 특히 의미·구조적 오류 유형(E3/E4/E_intent)에서 공용 프롬프트 대비 교정 성공률을 향상시키는가?"

### 3.2 서론 (§1.3 연구 기여)
기여 1번을 다음으로 교체:

> **의도 일치 검증기(ICC)를 독립 진단 축으로 제안** — SQL을 자연어로 역번역한 뒤 NLI로 함의 관계를 판정하는 모듈을 설계하고, 이를 실행 기반 검증과 **병렬 배치**해 실행이 성공한 쿼리 중 사용자 의도와 불일치하는 경우를 포착한다. 본 연구는 ICC를 EX의 보조 지표가 아니라 **독립 진단 지표**(E_intent Exclusive Detection, EIED)로 제시함으로써, 실행 정확도라는 단일 축이 가리는 의미 오류의 규모를 정량화한다.

### 3.3 제2장 §2.3 (NLI 관련 연구)
기존 본 연구와의 차별점 (c) 보강:
> (c) 이 축을 실행 검증과 **병렬로** 배치해, NLI가 *탐지하는* 오류 집합과 실행 검증이 *탐지하는* 오류 집합의 **집합-차(set difference)를 명시적으로 측정**함으로써, 두 검증 축의 상호보완성을 정량화한다.

### 3.4 제3장 §3.2 (오류 분포)
현재 공란 상태. 본 실험 후 다음 표로 채운다:

**표 (신설) — 검증 축별 오류 포착 Venn**
| 분류 | 정의 | 건수 | 비율 |
|---|---|---|---|
| 실행축만 포착 | Exec fail AND NLI pass | | |
| NLI축만 포착 | Exec pass AND NLI fail | | **← EIED 핵심** |
| 양축 모두 포착 | Exec fail AND NLI fail | | |
| 양축 모두 통과(정답) | Exec pass AND NLI pass AND EX=1 | | |
| 양축 모두 통과(오답) | Exec pass AND NLI pass AND EX=0 | | **← 잔여 사각지대** |

### 3.5 제5장 §5.2.2 (평가 지표)
ICS 정의 다음에 EIED를 추가:
> **EIED (E_intent Exclusive Detection)**: 실행 검증을 통과한 쿼리 중 실제로는 EX=0인 사각지대 쿼리 집합에서, NLI가 `ICS < θ`로 포착한 비율. `EIED = |{q : EX(q)=0 ∧ exec_valid(q)=True ∧ NLI(q,q')<θ}| / |{q : EX(q)=0 ∧ exec_valid(q)=True}|`

### 3.6 제5장 §5.5 (어블레이션) — 재해석 문단 교체
BEFORE: "Full 50% vs A1 52% → 표본 변동, gating 효과"
AFTER: "Full 50% vs A1 52%는 1건 차이이며, NLI 트리거가 **EX 지표에 대해서는** 한계 효용이 미미함을 시사한다. 다만 동일 실험에서 E_intent 탐지율 66%, EIED=[본 실험]%로 측정되어, NLI 축은 **EX 향상 도구가 아닌 독립 진단 축**으로서의 가치가 분리 측정된다. RQ1의 답은 'EX 향상 기여 Null, 탐지 기여 유의'로 이원화된다."

### 3.7 제6장 §6.1 (RQ1 고찰) — 결론 이원화
> **RQ1의 답은 이원적이다.** (a) *교정 루프 관점*에서 NLI 트리거의 EX 향상 기여는 파일럿·본 실험 모두에서 통계적으로 유의하지 않았다. 이는 GPT-4o급 고성능 LLM의 초기 SQL 신뢰도가 매우 높아 교정 개입 여지가 작다는 구조적 한계에 기인한다. (b) *진단 관점*에서는 NLI가 실행 검증 통과 쿼리 중 오답의 **[EIED]%**를 단독 포착하며, 이는 실행 정확도가 가리는 사각지대의 정량화에 기여한다. 본 연구는 ICC를 **교정 트리거가 아닌 독립 안전 지표**로 배치하는 설계가, GPT-4o급 이상 모델을 사용하는 실무 환경에서 더 가치 있는 운영 패턴임을 제안한다.

### 3.8 제6장 §6.4 (결론) — 기여 재정렬
세 기여의 순서·강조 변경:
1. **(기존 3→1)** 스키마-온리 평가 프로토콜 (경험적으로 HRDB +20pp로 실증됨)
2. **(기존 1 재포지션)** 의도 일치 검증기의 **독립 진단 축** 설계 (EIED로 정량화)
3. **(유지)** 유형별 분기 교정기 (E3/E4/E_intent 한정 유효성)

## 4. 필수 신규 측정 (본 실험 시 포함)

### 4.1 실험 분석 파이프라인 추가
`evaluate.py`에 다음 필드를 per-sample 로그에 추가:
- `exec_validator_pass`: 실행 검증기가 "성공"으로 판정했는가 (현재도 있음)
- `nli_ics`: ICS 값 (현재도 있음)
- `nli_flag`: ICS < θ 인가
- `final_ex_correct`: 최종 EX gold 매칭 여부

### 4.2 집계 스크립트
`scripts/compute_eied.py` 신설:
```python
# 의사코드
exec_pass = df[df["exec_validator_pass"] == True]
blind_spot = exec_pass[exec_pass["final_ex_correct"] == False]
eied = blind_spot["nli_flag"].mean()  # NLI가 잡은 비율
print(f"EIED = {eied*100:.1f}%")
```

### 4.3 기대 수치
- 파일럿 추정(n=50, Full): blind_spot = 50-4=46 실행 통과 중 오답 약 23건. 이 중 NLI가 잡은 건 약 16-17건 → **EIED ≈ 70%** 예상.
- 이 추정이 n=1,534에서도 40% 이상 유지되면 RQ1(Detection)은 강한 근거 획득.

## 5. 리스크 & 반박 대응

| 심사자 반박 | 본 논문 방어 |
|---|---|
| "EIED가 높아도 결국 EX가 안 오르면 무슨 소용?" | §6.1 (b) — 운영 환경에서 EIED는 **사용자 경고·HITL 트리거** 용도로 가치가 있음. EX 자동 향상은 별개 과제. |
| "NLI가 그냥 'LLM-as-judge'의 일종 아닌가?" | §2.3 (a), §4.4.2 — 전용 cross-encoder이므로 비결정성·비용·환각 없음. 양방향 평균으로 편향 완화. |
| "RQ1이 이원적이면 주장이 약해지지 않나?" | "하나의 방향으로 강하게 주장하는 것"보다 "관측 사실을 정확히 분해 보고하는 것"이 과학적으로 우수함. 이는 실무 도입 가이드라인(gpt-4o급에서는 교정 아닌 진단 용도)으로 직접 이어짐. |
| "EIED 70%라도 나머지 30%는 잡지 못함" | 한계(§6.3)에 명시. 향후 연구(§6.3 한국어 NLI 교체, HITL)로 연결. |
